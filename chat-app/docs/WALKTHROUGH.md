# Local demo walkthrough

Use the [README](../README.md) to start either Compose or the Windows-native services. Real Docker, Keycloak and PostgreSQL end-to-end verification is **deferred until the user reboots**; the steps below describe the intended live walk-through, not a passed E2E result.

1. Open `http://localhost:3000/admin` or the configured host/port. Sign in with the app `admin` account (password `admin` unless changed at creation via `SWISS_DISCOVER_ADMIN_PASSWORD`) and register your MCP servers. Existing registries are preserved. Ordinary registered users cannot access this form. For phones, configure `PUBLIC_HOST` before first realm import and use the same host for all browser-facing URLs.
2. Choose a registered MCP. The public detail/health check does not require login; health shows backend-to-MCP reachability, not model/auth readiness. Open Chat, choose registration in Keycloak, create a user, and sign in. The web client uses authorization-code PKCE (S256); Keycloak issues access tokens with audience `swiss-discover-api`, which FastAPI validates. The browser stores tokens in `sessionStorage`, not the database or `.env`.
3. Create a conversation. Backend reads the selected MCP's initialization instructions and tool list, saves snapshots, and sends the instructions as **untrusted user-context data** after its trusted system safety message. Missing instructions are allowed. Tool approvals follow the snapshotted policy/annotations.
4. Send a message and watch reasoning (if emitted), text, tool arguments/results and any approval prompt. The default `ask_destructive` policy skips approval on read-only annotated tools; to demonstrate approval set `ask_always` in `/admin` and create a new conversation. Images require `LLM_IMAGE_INPUT=supported` on a verified endpoint; see [provider notes](PROVIDER.md).
5. Refresh or briefly disconnect while a run is active. The frontend reconnects using the last SSE sequence (`?after=`), and the backend replays persisted events without starting another tool execution. Only the newest 512 events per run are kept; a cursor older than that window cannot recover missing deltas. Reload conversation detail to recover the persisted message and tool state. Cancel an active run before deleting its conversation.
6. Open history to find saved conversations, then delete one to remove its messages, tool calls, runs/events and attached images. Unattached uploads older than 24 hours are purged at backend startup (not continuously). A backend restart marks interrupted runs failed and releases locks; it **does not** resume or rerun them. Deploy exactly one backend worker.

For an external-client demo use the separate [client guide](CLIENTS.md): Configure shows endpoint metadata, but a localhost or Docker-internal `/mcp` address is not accessible to a cloud connector. Static bearer auth for MCP servers is independent of Keycloak and is not MCP OAuth.
