# Local demo walkthrough

Use the [README](../README.md) to start either Compose or the Windows-native services. Real Docker, Keycloak and PostgreSQL end-to-end verification is **deferred until the user reboots**; the steps below describe the intended live walk-through, not a passed E2E result.

1. Open `http://localhost:3000` or `http://<PUBLIC_HOST>:3000` on the same LAN. For phones, configure `PUBLIC_HOST` **before first realm import**, open firewall ports 3000, 8000 and 8080, and use the same laptop IP for all browser-facing URLs. The admin credential is only for Keycloak administration.
2. Choose **Zurich Transit (demo)** or **Museum Guide (demo)**. The public detail/health check does not require login; health shows backend-to-MCP reachability, not model/auth readiness. Open Chat, choose registration in Keycloak, create a user, and sign in. The web client uses authorization-code PKCE (S256); Keycloak issues access tokens with audience `swiss-discover-api`, which FastAPI validates. The browser stores tokens in `sessionStorage`, not the database or `.env`.
3. Create a conversation. Backend fetches the selected MCP `general_context` prompt and tool list once, saves snapshots and sends the prompt as **untrusted user-context data** after its own trusted system safety message. Ask the transit demo for fictional departures from a named stop, or ask the museum for an exhibit in its fictional catalog. Neither MCP calls a real data API. Tool calls and their outputs are untrusted data; tool approvals follow the snapshotted policy/annotations.
4. Send a message and watch reasoning (if emitted), text, tool arguments/results and any approval prompt. The default `ask_destructive` policy skips approval on read-only annotated demo tools; to demonstrate approval use `ask_always` on a registry entry and seed it again. Do not present Swisscom reasoning as verified: the saved reasoning probes received HTTP 429. Images require `LLM_IMAGE_INPUT=supported` on a verified endpoint; see [provider notes](PROVIDER.md).
5. Refresh or briefly disconnect while a run is active. The frontend reconnects using the last SSE sequence (`?after=`), and the backend replays persisted events without starting another tool execution. Only the newest 512 events per run are kept; a cursor older than that window cannot recover missing deltas. Reload conversation detail to recover the persisted message and tool state. Cancel an active run before deleting its conversation.
6. Open history to find saved conversations, then delete one to remove its messages, tool calls, runs/events and attached images. Unattached uploads older than 24 hours are purged at backend startup (not continuously). A backend restart marks interrupted runs failed and releases locks; it **does not** resume or rerun them. Deploy exactly one backend worker.

For an external-client demo use the separate [client guide](CLIENTS.md): Configure shows endpoint metadata, but a localhost or Docker-internal `/mcp` address is not accessible to a cloud connector. Museum static bearer auth is independent of Keycloak and is not MCP OAuth.
